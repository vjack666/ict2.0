# Bitácora — Eliminación de OTE y consolidación ICT FVG + OB

**Fecha:** 2026-08-17 15:30 UTC-5  
**Estado:** APLICADO en `main`  
**Alcance:** limpieza de OTE del modelo operativo y consolidación de FVG/Order Block como zonas principales de entrada.

## Motivo

Se decidió eliminar OTE (Optimal Trade Entry) del sistema para trabajar con un modelo ICT más directo: liquidez, estructura, displacement y retorno a PD Arrays, con especial foco en **FVG + Order Block**.

## Decisión operativa

La cadena canónica queda:

`HTF bias → liquidez → sweep → displacement → BOS/CHOCH → FVG/OB → retorno/retest → entry → SL estructural → TP en liquidez`

Premium/Discount y EQ 50% permanecen como contexto de dealing range, pero no existe ningún requisito Fibonacci de 62–79%.

## Cambios aplicados

1. `analysis/ict_agent.py`
   - Eliminado el bonus de confianza basado en la presencia de `OTE`.
   - Premium/Discount queda como contexto.
   - FVG y Order Block permanecen como eventos ICT explícitos.

2. `docs/reglas/ICT_RULEBOOK.md`
   - Eliminada la sección OTE como componente operativo.
   - Eliminados Fibonacci 62–79%, OTE gate y OTE score.
   - Añadida cadena canónica de entrada basada en FVG/OB.
   - FVG + OB stacking pasa a ser confluencia explícita.

3. `docs/INDICE_AUTORIDAD.md`
   - Registrada la enmienda v1.1 como autoridad vigente.
   - OTE queda explícitamente fuera de la autoridad operativa.

4. `docs/ict/SPEC_TESIS_FORMAL_V1.1_AMENDMENT_OTE_REMOVAL.md`
   - Nueva enmienda formal que sobrescribe las referencias operativas a OTE.
   - Se conserva el SPEC v1.0 original para trazabilidad histórica.

## Regla de protección

No se debe reintroducir OTE mediante nombres alternativos como `optimal_entry`, `fib_entry`, `retracement_zone`, `ote_score` o equivalentes cuyo propósito sea reproducir el mismo gate.
