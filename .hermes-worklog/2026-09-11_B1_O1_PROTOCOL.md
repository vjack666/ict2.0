## 2. Definiciones ICT congeladas

### HTF context
- `engine/bos.py` — `StructureConfig(swing_lookback=5, confirm_bars=2)`
- `engine/market_features.py` — `build_features(df)` genera bos_dir, choch_dir, trend, swings

### Sweep
- `engine/turtle_soup.py` — `is_turtle_soup()` detecta barrido PDH/PDL del día previo + reversión
- `engine/turtle_soup.py` — `_has_reversal()` cuerpo >= 0.6*rango en ~20 velas
- `engine/turtle_soup.py` — `flag_turtle_soup()` anota sweep en señales

### Displacement
- `detectors/displacement.py` — `DisplacementConfig(body_range_multiple=1.5, wick_threshold=0.4, range_period=14)`
- `detectors/displacement.py` — `detect_displacement()` genera displacement_bullish/bearish, displacement_magnitude

### BOS
- `engine/bos.py` — `detect_market_structure()` genera bos_dir, choch_dir, bos_status, choch_status, trend, swings

### CHOCH
- `engine/bos.py` — `detect_market_structure()` genera choch_signal, choch_status

### FVG
- `detectors/fvg.py` — `detect_fvg()` detecta gap de precio (low > prev2_high / high < prev2_low)
- `detectors/fvg.py` — genera fvg_bullish, fvg_bearish, fvg_size, fvg_mid, fvg_fill_status

### OB
- `detectors/ob.py` — `detect_order_blocks()` genera ob_bullish, ob_bearish, ob_top, ob_bottom

### Retest
- Por definir: retest = 가격 que vuelve a una zona FVG/OB después de la formación

### Timing
- M15 es el timeframe de decisión para B1 (nivel de entrada)
- H4/H1/D1 son contexto HTF
- Sesión Londres/NY según contrato CRO

## 4. Requisitos de calidad

### No duplicates
- Cada `candidate_id` debe ser único.
- No reentradas del mismo episodio.
- Duplicados por diferentes TF → registrar y decidir clasificación.

### Timestamps válidos
- Todos los timestamps deben ser UTC.
- No pueden haber timestamps futuros respecto al dataset.
- Orden cronológico estricto.

### Closed-bar
- Decisiones solo sobre barras cerradas.
- No usar información intra-barra.

### Lineage
- Cada feature debe rastrear su fuente hasta los parquets originales.
- source_refs debe permitir reconstruir de dónde salió cada columna.

### No future leakage
- source_time <= decision_time para todas las features.
- No rolling con futuro.
- No merge_asof incorrecto.
- No objetos confirmados retroactivamente.
- No retest detectado antes de ocurrir.
- No resultado económico filtrándose en features.

### Candidate_id estable
- El mismo candidate_id debe identificar el mismo setup en todas las ejecuciones.

### Net_R trazable
- Cada net_R debe poder reconstruirse desde entry, SL, TP, costs, exit.
- Costs congelados según contrato CRO.

### Manifest congelado
- B1_DATA_MANIFEST_V1.json congelado antes de extracción.
- dataset_manifest_hash registrado en cada fila.

## 6. Auditoría causal (Departamento A)

### Revisión de features antes de conclusiones económicas

El departamento A debe verificar:

1. **Decision_time:** cada feature usa información disponible en ese instante.
2. **Event_time:** los eventos (sweep, displacement, BOS, CHOCH, FVG, OB) tienen timestamps coherentes.
3. **Confirmation_time:** la confirmación de estructura no usa barras futuras.
4. **Source_time:** los datos fuente son anteriores o iguales a decision_time.

### Regla principal

```
source_time <= decision_time
```

### Buscar

- Shift incorrecto (off-by-one)
- Rolling con futuro (window que mira adelante)
- Merge_asof incorrecto (asof que usa futuro)
- Objetos confirmados retroactivamente
- Retest detectado antes de ocurrir
- Resultado económico filtrándose en features

### Entregable

`reports/b1/causal_audit_design_2006_2015.md` con:
- Lista de features auditadas
- Hallazgos
- Veredicto por feature

## 8. Red Team (Departamento E)

### Búsqueda de problemas

1. **HOLDOUT accidental:** verificar que ningún dato de HOLDOUT (2021+) se usó en DESIGN.
2. **Leakage:** verificar que no hay features que usan información futura.
3. **Duplicados:** verificar que cada candidate_id es único.
4. **TF mezclados:** verificar que no hay filas de diferentes TF para el mismo setup sin documentar.
5. **Clasificación posterior al resultado:** verificar que las categorías no se asignan mirando net_R.
6. **Pérdida de candidatos negativos:** verificar que se registran también los setups que NO producen señal.
7. **Exclusiones no documentadas:** verificar que todas las exclusiones tienen razón registrada.
8. **N artificialmente reducido:** verificar que no se excluyeron candidatos de forma arbitraria.
